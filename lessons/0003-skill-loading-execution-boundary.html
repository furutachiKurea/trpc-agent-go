Skill 的加载与执行边界

这一课只讲框架通用能力：Skill 如何被发现、加载，以及脚本为什么不由 skill_load 执行。这个边界是读懂 issue #2004 的基础。

Skill 是什么

在 tRPC-Agent-Go 中，Skill 是一个目录，核心是 SKILL.md，旁边可以有 docs 和 scripts。它表达的是可复用工作流，而不是一个 Go 类型或一个普通函数。

skills/
  demo/
    SKILL.md
    docs/usage.md
    scripts/check.sh

启用 Skill

通用 API 形状如下：

repo, err := skill.NewFSRepository("./skills")
if err != nil {
    return err
}

agt := llmagent.New(
    "skills-agent",
    llmagent.WithSkills(repo),
    llmagent.WithCodeExecutor(exec),
    llmagent.WithEnableCodeExecutionResponseProcessor(false),
)

WithSkills 让 agent 知道有哪些 skill，并注册内置 skill 工具。WithCodeExecutor 让 workspace 执行工具可用。关闭 fenced-code 自动执行，是为了避免把“工具执行”和“回复里的 Markdown 代码块自动执行”混在一起。

三层信息模型

层 发生了什么
Overview 框架把 skill 的 name 和 description 注入上下文，让模型知道可选 skill。
Body / docs 模型需要时调用 skill_load，框架把 SKILL.md 正文和选定 docs 材料化到请求中。
Scripts 脚本不会被内联到 prompt；需要执行时通过 workspace 执行工具在隔离 workspace 中运行。

四个常见误解

skill_load 不是运行脚本

它加载知识材料。脚本执行属于 workspace 执行。

WithSkills 不等于生产沙箱

文档说明没有显式 executor 时可能有 local fallback；生产语境应显式理解 executor 选择。

docs 选择要克制

Skill docs 是按需选择的，避免把整个知识库一次性塞进上下文。

SkillLoadMode 是生命周期概念

它影响 loaded skill 状态在 turn 或 session 中如何保留，不是执行模式。

和 issue #2004 的关系

issue 里说 code-review Skill 要包含 SKILL.md、规则文档、脚本目录和使用说明。背景含义是：规则和说明作为可加载知识，脚本作为可执行资产；两者由不同机制进入 Agent 工作流。

你需要掌握的是框架边界：知识加载归 Skill 工具，程序执行归 workspace / code executor，安全治理归 PermissionPolicy 或安全 wrapper。

练习

1. skill_load 成功后，脚本会自动运行吗？

不会。skill_load 只加载 SKILL.md 正文和 docs；脚本执行要通过 workspace 执行工具。

2. WithCodeExecutor 的直接意义是什么？

让 agent 拥有 code execution / workspace execution 能力。它不等于自动运行 assistant 回复中的所有 Markdown 代码块。

3. 为什么 docs/scripts 要分开理解？

docs 是上下文知识，会进入模型请求；scripts 是可执行资产，应在 workspace 中运行，并受执行治理约束。
