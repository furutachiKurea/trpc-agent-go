最小 Agent 运行闭环

这一课不讲代码评审需求，只讲 tRPC-Agent-Go 的最小可运行模型：模型、LLMAgent、Runner、Run、Event、Session。你先能跑通这个闭环，后面的工具、Skill、沙箱和报告才有位置挂。

先记住一张图

用户消息 runner.Run Invocation LLMAgent model.GenerateContent Event Session

Runner 是应用侧调用入口。它拿到用户、session 和消息，构造 invocation，调用 Agent，然后把 Agent 返回的事件流交给调用方，同时把非 partial 响应追加到 session。

四个对象的职责

对象 你应该怎么理解 常见 API
model.Model 模型适配器。真实模型、mock 模型、deterministic 模型都实现同一个接口。 GenerateContent、Info
llmagent.LLMAgent 把模型、指令、工具、Skill、输出约束组合成一个 Agent。 llmagent.New、WithModel、WithTools
runner.Runner 外层执行器。管理 session、invocation ID、事件处理、完成事件和插件。 runner.NewRunner、Run、Close
event.Event 运行时观察窗口。文本、工具调用、工具结果、错误、结构化输出都从这里看。 Error、Response、StructuredOutput、IsRunnerCompletion

最小真实模型版本

func buildRunner() runner.Runner {
    m := openai.New("gpt-4o-mini")

    a := llmagent.New(
        "assistant",
        llmagent.WithModel(m),
        llmagent.WithInstruction("Answer clearly and briefly."),
    )

    return runner.NewRunner("demo-app", a)
}

这只说明框架组合方式。真实运行还需要 provider 的 API key；但学习框架时，不应该把“模型服务是否可用”和“Runner/Agent 怎么组合”混在一起。

事件消费不是随便 range

events, err := r.Run(ctx, userID, sessionID, model.NewUserMessage(input))
if err != nil {
    return err
}

for evt := range events {
    if evt.Error != nil {
        return fmt.Errorf("agent event error: %s", evt.Error.Message)
    }

    if evt.StructuredOutput != nil {
        // typed or untyped structured result, depending on the option used
    }

    if evt.IsRunnerCompletion() {
        break
    }
}

Response.Done 不一定等于整次运行结束。文档建议以 Runner completion event 作为完成信号，尤其是涉及工具或图式流程时。

fake model 为什么重要

实现复杂 Agent 时，不要把所有验证都绑到真实模型。框架的 model.Model 是接口；测试或 dry-run 可以实现一个 deterministic model：它记录请求，按脚本返回工具调用、工具结果后的最终回答，或者直接返回结构化输出。

type scriptedModel struct {
    responses []*model.Response
}

func (m *scriptedModel) Info() model.Info {
    return model.Info{Name: "scripted"}
}

func (m *scriptedModel) GenerateContent(
    ctx context.Context,
    req *model.Request,
) (<-chan *model.Response, error) {
    ch := make(chan *model.Response, len(m.responses))
    go func() {
        defer close(ch)
        for _, resp := range m.responses {
            select {
            case <-ctx.Done():
                return
            case ch <- resp:
            }
        }
    }()
    return ch, nil
}

这个能力和具体代码评审规则无关。它解决的是“如何在没有真实模型 API key 时验证 agent 链路”这个框架使用问题。

练习

1. 为什么 Runner 比直接调用 Agent 更适合作为入口？

Runner 集成了 session、invocation ID、事件处理、完成事件、插件和运行选项。直接调用 Agent 会绕开这些应用层职责。

2. fake model 应该 fake 哪一层？

fake model.Model，不是 fake Runner。这样仍能走真实 LLMAgent、工具、事件和 session 链路。

3. 为什么只看最终文本不够？

工具调用、权限决策后的工具结果、错误、结构化输出和 usage 都在事件里。最终文本只覆盖一部分行为。
