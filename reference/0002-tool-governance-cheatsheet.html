Reference 0002

Tool Governance 速查

tRPC-Agent-Go 中工具治理的三层边界：可见、自动执行、执行前审批。issue #2004 里的高风险命令治理主要落在第三层。

三层边界

机制 判断时机 控制什么 典型结果
ToolFilter 构建工具表面时 模型能不能看到某个 tool 隐藏或展示 tool
ToolExecutionFilter 模型发出 tool call 后 框架是否自动执行这个 tool call 自动执行，或停下来交给宿主执行
PermissionPolicy tool 即将执行前 这次具体调用是否允许执行 allow、ask、deny

PermissionDecision

allow

允许框架继续执行 tool call。

ask

不执行 tool call，返回 approval required。它不是“等待用户批准后继续执行”的机制。

deny

不执行 tool call，返回 denied 和原因。

最小 API 形状

func policy(
    ctx context.Context,
    req *tool.PermissionRequest,
) (tool.PermissionDecision, error) {
    if req.Metadata.Destructive {
        approved, err := askHostApplication(ctx, req)
        if err != nil {
            return tool.PermissionDecision{}, err
        }
        if !approved {
            return tool.DenyPermission("user rejected destructive tool"), nil
        }
    }
    return tool.AllowPermission(), nil
}

events, err := r.Run(
    ctx,
    userID,
    sessionID,
    model.NewUserMessage(text),
    agent.WithToolPermissionPolicyFunc(policy),
)

这是通用 API 用法，不是 issue #2004 的实现方案。真实 policy 可以读 role、tenant、tool name、arguments、metadata 或业务上下文。要让工具执行，policy 必须返回 allow；返回 ask 会跳过本次执行。

读取 PermissionRequest

字段 用途
ToolName 模型可见的 tool 名。适合按工具类型分流。
Arguments 修复和 before-tool callback 后的 JSON 参数。适合检查命令、路径、环境变量。
Metadata 工具发布的安全元数据，如 read-only、destructive、search/read。
ToolCallID 关联模型发出的具体 tool call。适合审计记录。
