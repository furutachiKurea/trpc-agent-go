Skills 与 CodeExecutor 速查

issue #2004 会同时用到可复用工作流和隔离执行。这个速查只记录通用框架 API，不提供 issue 专属实现方案。

Skill 的三层信息模型

层 框架行为 你要记住的边界
Overview 注入 skill 的 name 和 description。 让模型知道有什么 skill，但不加载全文。
skill_load 按需加载 SKILL.md 正文和选定 docs。 加载知识，不执行脚本。
workspace_exec 在 workspace 中执行命令或脚本。 执行发生在 executor 提供的 workspace。

启用 Skill 的常见形状

repo, err := skill.NewFSRepository("./skills")
if err != nil {
    return err
}

agt := llmagent.New(
    "skills-agent",
    llmagent.WithSkills(repo),
    llmagent.WithCodeExecutor(exec),
    llmagent.WithEnableCodeExecutionResponseProcessor(false),
)

WithSkills 注册知识注入工具；WithCodeExecutor 让执行类工具可用；fenced-code 自动执行是独立开关。

CodeExecutor / Workspace 的核心结构

类型 含义
RunProgramSpec 一次程序执行请求：命令、参数、环境变量、cwd、stdin、timeout、资源限制。
RunResult 一次执行结果：stdout、stderr、exit code、duration、timed out。
InputSpec 把 artifact、host 路径、workspace 路径或 skill 文件映射到 workspace。
OutputSpec 声明要收集的输出、文件数限制、单文件/总大小限制、是否保存 artifact。
Capabilities.SupportsCleanEnv 当前 executor 是否能在执行命令时丢掉宿主环境，只使用框架明确传入的环境。配置 WithWorkspaceExecAllowedCommands / WithWorkspaceExecDeniedCommands 后，workspace_exec 会依赖它；不支持就拒绝执行。

SupportsCleanEnv 的触发点

agt := llmagent.New(
    "worker",
    llmagent.WithCodeExecutor(exec),
    llmagent.WithWorkspaceExecAllowedCommands("go", "git", "cat"),
)

这段配置表示：模型可以用 workspace_exec 跑命令，但命令必须在白名单里。为了让这个限制不是“只看命令名”的弱约束，框架还要求 executor 支持干净环境启动。

你做了什么 框架行为
只配置 WithCodeExecutor workspace_exec 可用；命令执行按 executor 默认行为走。
再配置 allowed / denied commands workspace_exec 进入 policy mode，命令需要通过结构检查和命令名策略。
executor 声明 SupportsCleanEnv=true policy mode 可以执行，子进程从干净环境启动。
executor 不支持 CleanEnv policy mode 直接失败，避免安全策略被静默降级。

RunResult 的判断顺序

  1. 先看是否有 Go error：这通常表示 runtime 层失败。
  2. 再看 TimedOut：命令是否超时。
  3. 再看 ExitCode：程序是否以非零状态退出。
  4. 最后读取 Stdout / Stderr：提取诊断输出。

非零 exit code 不一定是 Go error。它通常是程序自己的结果，需要从 RunResult 里判断。
