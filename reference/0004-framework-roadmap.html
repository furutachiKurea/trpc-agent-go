tRPC-Agent-Go 框架学习路线图

从“会写一个完整 Agent”倒推的学习路线。先掌握框架主干，再理解代码评审任务会用到的安全、存储、可观测和报告背景。

主干心智模型

model.Model llmagent.New runner.NewRunner runner.Run event stream session service tools / skills / executor structured output

框架应用不是从一个固定 main.go 开始，而是围绕 Agent 和 Runner 组合。LLMAgent 挂模型、指令、工具、Skill、结构化输出等能力；Runner 负责 session、invocation、事件流和完成事件。

应该先学什么

顺序 能力 为什么实现任务时会遇到
1 最小 LLMAgent + Runner 闭环 任何可执行 Agent 都要有模型、Agent、Runner、输入消息、事件消费。
2 事件流和完成条件 工具调用、工具结果、最终回答、错误和结构化输出都通过 event 暴露。
3 fake model / deterministic model 无真实 API key 时仍要验证完整链路，必须知道如何让模型行为可控。
4 Function Tool、ToolSet、Tool Filter、PermissionPolicy Agent 需要探索代码库和执行检查，但执行前必须有可治理边界。
5 Skill 加载与 workspace 执行 Skill 是可加载知识和工作流，不等于直接执行脚本；执行通过工具进入 workspace。
6 CodeExecutor / Workspace / RunResult 运行测试、静态检查或脚本时，要理解工作区、输入、输出、退出码，以及命令白名单依赖的干净环境能力。
7 Session / SQLite storage 可复查系统需要保存 run、事件、状态、审计记录和报告相关数据。
8 Telemetry / callbacks 耗时、工具调用、异常、权限拦截和模型行为需要可观测。
9 structured output 需要同时使用 tools 和产出结构化结果时，应避开会禁用工具的输出方式。
10 unified diff 和 Go 代码评审背景 Agent 能力只是载体；判断问题还需要 diff、行号、Go package、test/vet 等领域知识。

最小代码骨架

modelInstance := openai.New("gpt-4o-mini")

agentInstance := llmagent.New(
    "assistant",
    llmagent.WithModel(modelInstance),
    llmagent.WithInstruction("Be concise and use tools when useful."),
)

r := runner.NewRunner("my-app", agentInstance)
defer r.Close()

events, err := r.Run(
    ctx,
    "user-1",
    "session-1",
    model.NewUserMessage("hello"),
)
if err != nil {
    return err
}

for evt := range events {
    if evt.Error != nil {
        return fmt.Errorf("agent event error: %s", evt.Error.Message)
    }
    if evt.IsRunnerCompletion() {
        break
    }
}

这段骨架是后面所有能力的挂载点：工具挂到 LLMAgent，session service 挂到 Runner，单次运行策略通过 runner.Run 的 options 注入。

常见误区

把 Agent 当命令行程序

框架核心是可组合运行单元。CLI 只是宿主；Agent 本身通过 Runner、Session 和 Event 与外界交互。

只看最终文本

工具调用、权限拒绝、结构化输出、错误和 token usage 都可能在事件中。只看最终文本会漏掉系统行为。

把测试等同真实模型

框架层测试通常用 fake model 控制请求和响应。真实模型验证是另一类问题。

把 Storage 当聊天历史

Session 保存的不只是聊天上下文，还可以承载状态、事件和后续审计所需的数据入口。
